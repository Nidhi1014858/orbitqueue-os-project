# Section 6: Experiment 9 — Deadlock Avoidance with Banker's Algorithm

## Aim

To implement Banker's Algorithm and use it to decide whether CPU slots (A), buffer units (B), and transmitter slots (C) can be granted without leaving the OrbitQueue simulation in an unsafe state.

## Use-case connection

Five tasks declare maximum resource needs: T0 TelemetryHandler, T1 PacketRouter, T2 SSTVProcessor, T3 VoiceCodec, and T4 DownlinkPrep. A circular-wait risk exists if DownlinkPrep holds buffer units while waiting for a transmitter slot and PacketRouter holds the transmitter slot while waiting for buffer units. Banker's Algorithm is an avoidance mechanism: it checks whether every tentative grant still permits some completion order.

## Program and steps

1. Validate that Allocation, Max, and Available contain no negative values.
2. Reject Allocation values above Max, tasks with no declared resources, and impossible maximum claims.
3. Compute `Need = Max - Allocation`.
4. Copy Available to Work and find unfinished tasks whose Need is no greater than Work.
5. Simulate each such task finishing by adding its Allocation to Work.
6. The state is safe only if all five tasks can finish.
7. For a request, first reject values beyond Need, then return `WAIT` if Available is insufficient. Otherwise tentatively allocate, run the safety check, and either keep the grant or roll it back.

One internal mutex protects initialization, request, release, and snapshot operations used by the router's worker threads.

## Expected scenario behaviour

- S1 is safe with sequence T0, T1, T2, T3, T4.
- S3 has Available `(0,1,0)` and no task can initially finish, so it is unsafe.
- In S2, T1 requesting `(1,1,1)` is granted with sequence T1, T3, T4, T0, T2.
- T0 requesting `(1,2,1)` is tentatively possible but unsafe, so it is denied and rolled back.
- T2 requesting `(2,1,2)` waits because the available transmitter count is only one.
- T2 requesting `(1,2,0)` exceeds its declared buffer Need and returns `ERROR_EXCEEDS_NEED`.

## Post-lab answers

| Approach | OrbitQueue example |
|---|---|
| Prevention | Impose a fixed acquisition order, such as buffer units before the transmitter slot, to break circular wait. |
| Avoidance | Before granting buffer units or a transmitter slot, Banker's Algorithm checks that a safe completion sequence remains. |
| Detection | Build a wait-for/resource graph from tasks waiting for buffer units and the transmitter slot, then search for a cycle. |
| Recovery | Abort or roll back a deferrable SSTV task, releasing its buffer units and transmitter claim so critical work can continue. |

An unsafe state is not proof that deadlock has already happened. It means the declared remaining needs do not permit the algorithm to guarantee a safe order. A request can therefore be denied even when the requested units are currently available.

`Need` is the largest additional amount a task may still request: `Max - Allocation`. A safe sequence is a theoretical order in which every task could receive its remaining Need, finish, and release its Allocation.

## Conclusion

Banker's Algorithm avoids unsafe allocations by considering the complete declared resource state rather than only current availability. In OrbitQueue, that decision protects the simulated CPU, buffer, and transmitter resources from allocations for which safe completion cannot be guaranteed.
